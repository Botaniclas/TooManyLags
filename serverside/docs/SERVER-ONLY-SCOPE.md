# Server-only capability boundary - 0.13.1 Beta

| Feature | Implemented path | Limit |
|---|---|---|
| Public stationary chests | Automatic player/server grid ownership. Available remote owners use native RequestOpen to the headless server; onward player delegation waits for that native acquisition to settle. Empty-field returns assign directly. Stale opening requests follow the current owner. | Native opening-phase timing remains. No player-directed synthetic opening. Private/custom/unsupported mobile inventories, graves and incinerators stay native. |
| Directional ownership grid | Native character position/rotation; cached cells and object buckets. Full rear red 3x3; yellow off by default. | No client camera data. |
| Server default and exit | Managed objects return to the server outside player fields by default; native region releases remain intact | Explicit retention is available. Unsupported categories retain native/fork policy. |
| Fast forward row | Native replicated horizontal velocity selects precomputed immediate-orange masks at 4 m/s; release below 3 m/s | Replication delay remains. No extra polling cadence, network packets or player-position history. Existing handoff protection still applies. |
| Poor-connection coverage | Default expansion at 200 ms; native ping cached for one second, shrink below 150 ms. Cardinal red rows 3/5/5/3 plus three orange cells; diagonal grid approximation | Configurable threshold; zero disables. Unknown ping retains active size. Full-grid mode remains unchanged. |
| Immediate native controls | Doors, bed claims, wards, Pickables, collectors, feasts, map tables, refill controls and archery targets | Exact known stationary controls only; no inventories, moving roots or unknown callbacks. |
| Pure local controls | Seats, crafting menus and local markers have a server default and no grid node | Native local use is unchanged. Disabled categories stay native. |
| Player-to-server transfer | Direct-state groups keep the old owner during a cancellable two-ping window, minimum 0.1 s | Source updates cancel; only fresh field activity can retry. A ping estimate is not a delivery bound. |
| Server-to-player transfer | No added grace; a stale original request receives a targeted native state send before forwarding | Native sender ordering is not scene readiness or consent. Loaded single-interactor paths still need live testing. |
| Pickable completion | Native picked/destruction completion; no extra grace job | Completed picks are not forwarded again. Preserves native headless fixes from the dependency. |
| Observed refilling | Seven successful native server handlers plus native incoming fuel/queue/ammo/slot changes arm a one-second takeover veto. Repeated inserts refresh it; expiry does not replay | Remote local work remains invisible until transmitted. Coalescing can hide a net change. Consumption/cooking do not renew this veto. |
| Signs and portal editing | Entire identity stays outside the grid; normal native submission and dependency permissions | Editing start remains client-local and is not claimed to be observable. No guessed editing timer. |
| Other inventories, stands, deferred actions | Native/fork ownership and real user grants | No proactive transfer of their private client transaction state. |
| Idle tamed animals | Replicated tame flag; event-driven cell/state updates and native loaded-area checks for server takeovers | Following, riding, transport and combat suspend transfers. Friendly magic summons stay excluded. Unseen local actions are not acknowledged. |
| Riding requests | Preserve native request/reply recipients and grants; resume after observed dismount or a denied request | An unobserved accepted-grant completion can keep the native path until release/unload. No forced timeout. |
| Loose items | Indexed grid handoffs; nearby client owners and native pickup requesters retain priority. Leaving coverage releases protection, including failed pickup, teleport and disconnect. | Local pickup completion remains private. Exit retention, source-update and mobile loaded-area guards remain active. |
| Fish | Early server-to-player delegation; native pickup/grant/hook priority | Client/fishing ownership retains the previous unload-lifetime protection. Native ownership transfers still work. |
| Static buildings | Eligible noninteractive stationary Piece/WearNTear defaults to server ownership; optional grid sharing | Static grid defaults off. Server simulation can cost CPU. No PUP collider guard. |
| Actual ownership changes | Native setter event invalidates only the affected loaded node | Zero-owner native release is preserved. No periodic ownership scan. |
| Native boats | Helm-anchored grid: lone-player or overlapping-server ownership, native cargo permission/receipt checks and stale steering routing. Selectively replaces backend ownership writers only for managed boats. | Cargo opening still transfers the shared boat identity. Native opening-phase timing remains; no separate cargo owner. Server takeover requires loaded physics. |
| Native carts | Idle grid ownership; native cargo/source-pulling checks, Boolean joint events, pending remote hitch priority and native refusal/departure cleanup. | Already-owning clients do not publish local pending hitch starts. Unknown remote completion keeps request priority until departure; no guessed timeout or cart polling loop. |
| Hostile Mobs | Native MonsterAI/Humanoid creatures use grid ownership. Shared cells select the sole eligible cone player; zero or multiple players select the server by default. Optional nearest-player mode; separate normal 8-metre and native-boss 10-metre ranges | Server sources inspect actual Attack completion. Client sources use native trigger/animation observations, not a source grant; remote timing and private cooldown migration remain limits. Friendly player summons stay excluded. |
| Ability forecast | Optional player-source veto after existing attack guards: per-ability timestamps from native signals, 100-ms plus cached RTT reduction, padded attack geometry only for ready abilities and pending transfers, event-driven retry | Unknown/ambiguous alternatives stay ready. Native physics and remote events may be delayed. No exact AI replica, target identification, private global recovery timer or atomic permission; may retain an owner longer during combat. |
| Solo combat diagnostic | Optional one-player, one-mob alternating server/player requests through the normal guarded handoff path; disabled by default | Stops after five minutes or invalidation. No client requirement and no force-through of an attack guard; does not reproduce concurrent multiplayer inputs. |
| Unsupported creatures and vehicles | Native/fork handling | No custom AI rewrite, concrete target replication or collider system. |
| Dependency-specific policies | Boss stones and unsupported controls stay native. FireControl sources stay outside the grid by default; `RespectBackendFireOwnership=false` enables eligible refill/fireplace grid ownership without competing backend takeovers | Raw fires/disabled categories remain native. Server-only fire rules cannot be fully enforced on player-owned sources. Restart required. |

No custom client messages, DLL, handshake or connection requirement is introduced. Server startup validates the native packet envelope used by targeted routing; it does not hard-lock a game or dependency version number.

[Implementation details](HANDOFF-IMPLEMENTATION.md) explain the selected candidate. The earlier handoff research documents are historical assessments, not additional enabled features. No universal network/transaction guarantee or live multiplayer certification is claimed.
